# 데이터 파이프라인

> 캐릭터/스킬 등 게임 데이터를 관리하고 유니티로 가져오는 규칙

---

## 1. 데이터 흐름

- 원본은 구글 시트로 한다. 데이터 수정은 구글 시트에서만 한다.
- 흐름 : 구글 시트 → CSV 다운로드(`파일 > 다운로드 > CSV`) → `Assets/Data/CSV/`에 덮어쓰기 → 메뉴 `Tools > Data > Import CSV` 실행 → ScriptableObject 에셋 생성/갱신
- 변환 순서는 스킬 → 캐릭터다. 캐릭터가 스킬 Id로 고유 마법을 찾기 때문이다.

## 2. 파일 위치

| 구분 | 경로 |
|---|---|
| CSV | `Assets/Data/CSV/Skill.csv`, `Assets/Data/CSV/Character.csv` |
| 스킬 에셋 | `Assets/Data/Skills/Skill_{Id}.asset` |
| 캐릭터 에셋 | `Assets/Data/Characters/Character_{Id}.asset` |
| 변환 스크립트 | `Assets/Scripts/Editor/DataImporter.cs` |

## 3. Id 규칙

- Id는 여섯 자리 정수 `TUNNNN`으로 한다.

| 자리 | 의미 | 값 |
|---|---|---|
| T | 데이터 구분 | 캐릭터 `1`, 마법 `2~9` |
| U (마법) | 고유 여부 | 일반 마법 `1~5`, 고유 마법 `6~9` |
| U (캐릭터) | 소속 | `1~2`, `3~4`, `5~6`, `7~8`, `9` (소속 5개) |
| NNNN | 순서 | U마다 따로, 만들어진 순서대로 `0001`부터 |

- 각 범위에서는 작은 수부터 쓰고, 나머지 수는 예비로 둔다.
- 맨 앞자리(T)에는 0을 쓰지 않는다. 구글 시트와 정수 변환에서 맨 앞자리 0이 사라져 여섯 자리가 깨지기 때문이다.
- 고유 마법은 한 캐릭터만 가진다.
  - 예외 캐릭터는 사용자가 예외로 만들겠다고 확실하게 판단한 경우에만 만든다.
  - Claude는 예외 캐릭터를 임의로 만들지 않는다.

## 4. CSV 형식

- 첫 줄은 헤더(열 이름)이며, 변환 시 건너뛴다.
- 열 순서를 바꾸지 않는다. 순서를 바꾸려면 `DataImporter.cs`도 함께 수정한다.
- 한 칸 안에서 줄바꿈하지 않는다.
- 쉼표가 들어간 칸은 구글 시트가 큰따옴표로 감싸 내보내므로 그대로 둔다.

### Skill.csv

| Id | Type | Name | Icon | Description | Cooldown |
|---|---|---|---|---|---|
| Id 규칙에 따른 정수 | `Attack` / `Support` / `Disrupt` / `Move` | 문자열 | Sprite 경로(비워도 됨) | 문자열 | 소수 |

- `Type`은 `SkillType` enum 이름과 대소문자까지 똑같이 적는다.
- `Icon` 이미지는 Texture Type `Sprite (2D and UI)`, Sprite Mode `Single`로 설정한다.

### Character.csv

| Id | Name | Hp | Mp | MpRegen | MoveSpeed | Passive | Skill1Id | Skill2Id |
|---|---|---|---|---|---|---|---|---|
| Id 규칙에 따른 정수 | 문자열 | 정수 | 정수 | 소수 | 소수 | 문자열(임시) | 스킬 Id | 스킬 Id |

- `Passive`는 패시브 스킬 데이터 구조가 생기기 전까지 임시 문자열로 둔다.

## 5. 재변환 규칙

- 같은 Id의 에셋이 있으면 새로 만들지 않고 값만 갱신한다. 에셋을 참조하던 곳의 연결을 유지하기 위해서다.

### Id 변경 절차

Id를 바꾸면 변환 스크립트는 다른 에셋으로 보고 새 에셋을 만든다. 예전 에셋을 그대로 두면 이를 참조하던 곳이 갱신되지 않는 예전 데이터를 계속 가리키므로, 아래 순서를 지킨다.

1. 구글 시트에서 Id를 바꾼다. 마법 Id라면 캐릭터 시트의 `Skill1Id`, `Skill2Id`도 함께 바꾼다.
2. 예전 Id의 에셋을 삭제한다.
3. CSV를 다시 받아 변환한다.
4. 예전 에셋을 참조하던 씬/프리팹에서 `Missing`으로 표시된 칸에 새 에셋을 다시 연결한다.

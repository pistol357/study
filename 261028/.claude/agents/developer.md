## 입력

호출하는 쪽은 아래 항목을 전달한다. 빠진 항목이 있으면 작업하지 않고 되묻는다.

- 승인된 브리핑 (작업 범위, 생성/수정 파일, 작업 순서)
- 연결 이슈 번호 (있을 때)

## 절차

1. **규칙 확인**
   - 행동 규칙 `행동 원칙`(2. 단순함 우선, 3. 외과적 변경), `작업 범위 규칙`, `응답 규칙`을 읽는다.
   - Workflow `5. 업무 수행` > `작업 진행`을 읽는다.
2. **작업 대상 확인**
   - 브리핑의 생성/수정 파일이 실제로 있는지 확인한다.
   - 브리핑과 실제 상태가 다르면 작업하지 않고 보고한다.
3. **작업**
   - 소스코드 : 코드 컨벤션 전체와, 기술 스펙에서 작업에 해당하는 섹션(`유저 입력 시스템`, `UI` 등)을 따른다.
   - 게임 데이터(CSV, ScriptableObject) : 데이터 파이프라인에서 작업에 해당하는 섹션을 따른다.
   - 브리핑에 적힌 파일과 순서 안에서만 작업한다.
4. **보고** : 아래 형식으로 결과를 돌려준다.

## 금지 사항

- Git 작업(브랜치, 커밋, 푸시 등)을 하지 않는다.
- 브리핑에 없는 파일을 만들거나 고치지 않는다. 문제를 발견하면 보고만 한다.
- 작업 중 브리핑과 다르게 판단해야 하면 멈추고 보고한다.

## 보고 형식

```
## 개발 결과 : [작업명]

**변경 파일**
- 생성 : 파일경로(역할)
- 수정 : 파일경로(변경 내용)

**브리핑과 다른 점** (없으면 "없음")

**범위 밖 발견 사항** (없으면 "없음")

**미검증 사항**
- 직접 확인하지 못한 항목 (예 : 유니티 에디터 동작, 컴파일 에러 여부)
```

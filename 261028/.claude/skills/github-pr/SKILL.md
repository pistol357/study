# Github PR 등록

> 이 스킬은 절차와 멘트 규격만 정의한다.
>  
> PR 작성 규칙의 원본은 아래 문서이며, 규칙을 이 스킬에 옮겨 적지 않는다. 각 단계에서 지정된 섹션을 읽고 따른다.

| 문서 | 경로 |
|---|---|
| Workflow | `Docs\Claude\WorkflowRules.md` |
| Template | `Docs\Template\PRTemplate.md` |

## 절차

1. **작업 정보 확인**
   - Workflow `1. 업무 분류`, `5. 업무 수행`을 읽고, 현재 브랜치의 업무 분류와 연결 이슈를 확인한다.
   - Git은 상태 조회(`git branch --show-current`, `git status`, `git log`, `git diff main...HEAD --stat`)만 사용한다.
   - 현재 브랜치가 `main`, `Develop`이면 PR을 작성하지 않고 사용자에게 보고한다.
   - 연결 이슈가 불명확하면 사용자에게 질문한다.
2. **푸시 확인**
   - `git status -sb`로 원격 브랜치 존재 여부와 미푸시 커밋을 확인한다.
   - 푸시가 필요하면 `멘트 ①`로 안내하고, 사용자가 직접 푸시할 때까지 대기한다.
3. **초안 작성**
   - Workflow `9. PR 생성`과 Template의 양식을 읽고 초안을 작성한다.
   - 작업 내용의 파일 경로는 1단계에서 확인한 실제 변경 파일 기준으로 작성한다.
4. **승인 요청** : `멘트 ②`로 초안을 제시한다. 승인 전에는 등록하지 않는다.
5. **등록**
   - 본문은 스크래치패드에 파일로 저장 후 `gh pr create --base --head --title --body-file`로 등록한다.
   - 본문에는 승인받은 초안 외의 문구(생성 도구 표기 등)를 덧붙이지 않는다.
6. **보고** : `멘트 ③`으로 보고하고, Workflow `10. 병합`에 따라 병합 명령을 대기한다.

## 멘트 규격

> 아래 형식 외의 설명은 덧붙이지 않는다. `[ ]`는 상황에 맞게 채운다.

### ① 푸시 안내

````
PR 등록 전, 작업 브랜치의 푸시가 필요합니다. 아래 명령을 직접 실행해 주세요.

```
git push -u origin [브랜치명]
```

푸시가 끝나면 알려주세요.
````

### ② 초안 승인 요청

````
## PR 초안 : [Title]

```markdown
[Template 양식으로 작성한 본문]
```

- **Base ← Head** : [base 브랜치] ← [작업 브랜치]
- **확인 필요** : [임의로 정한 내용 등, 없으면 생략]

이대로 등록할까요?
````

### ③ 등록 완료 보고

```
PR 등록 완료

- **번호** : #[번호]
- **링크** : [URL]
- **Base ← Head** : [base 브랜치] ← [작업 브랜치]

검토 후 병합 명령을 주세요.
```

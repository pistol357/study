# Github Issue 등록

> 이 스킬은 절차와 멘트 규격만 정의한다.
>  
> 이슈 작성 규칙의 원본은 아래 문서이며, 규칙을 이 스킬에 옮겨 적지 않는다. 각 단계에서 지정된 섹션을 읽고 따른다.

| 문서 | 경로 |
|---|---|
| Rule | `Docs\Documentation\Github Issue Rule.md` |
| Template | `Docs\Template\IssuesTemplate.md` |
| Workflow | `Docs\Claude\WorkflowRules.md` |

---

## 절차

1. **업무 분류 확인**
   - Workflow `1. 업무 분류`를 읽고, 개발 / 버그 수정일 때만 진행한다.
   - 문서 작성이면 이슈가 필요 없음을 알리고 종료한다. 분류가 모호하면 사용자에게 질문한다.
2. **등록 권유** : 이슈가 없는 상태라면 `멘트 ①`로 이슈 등록을 권유한다.
3. **배경 / 목적 질문**
   - Rule `2. 배경 / 목적`을 읽고, `멘트 ②`로 질문한다.
   - 답변이 없으면 이슈를 작성하지 않는다.
4. **초안 작성**
   - Template의 양식과 Rule `1. Title` ~ `6. 특이 사항`, `7. 기타`를 읽고 초안을 작성한다.
   - 작업 내용 작성 전, 관련 파일/폴더의 실제 존재 여부를 확인한다.
5. **승인 요청** : `멘트 ③`으로 초안을 제시한다. 승인 전에는 등록하지 않는다.
6. **등록**
   - Rule `7. 기타`의 Label을 확인(`gh label list`)하고, 없으면 생성 후 할당한다.
   - 본문은 스크래치패드에 파일로 저장 후 `gh issue create --title --label --body-file`로 등록한다.
7. **보고** : `멘트 ④`로 보고하고, Workflow `2. 이슈 생성`에 따라 착수 명령을 대기한다.

## 멘트 규격

> 아래 형식 외의 설명은 덧붙이지 않는다. `[ ]`는 상황에 맞게 채운다.

### ① 등록 권유

```
이 요청은 **[개발 / 버그 수정]** 업무로, 착수 전 Github Issue 등록이 필요합니다.
이슈 작성을 진행할까요?
```

### ② 배경 / 목적 질문

```
이슈 작성을 위해 아래 정보가 필요합니다.

1. **배경 / 목적** : 이 작업이 왜 필요한가요?
2. [구현 방식 등 초안 작성에 필요한 추가 질문, 없으면 생략]
```

### ③ 초안 승인 요청

````
## 이슈 초안 : [Title]

```markdown
[Template 양식으로 작성한 본문]
```

- **Label** : [Label]
- **확인 필요** : [임의로 정한 경로/이름 등, 없으면 생략]

이대로 등록할까요?
````

### ④ 등록 완료 보고

```
이슈 등록 완료

- **번호** : #[번호]
- **링크** : [URL]
- **Label** : [Label]

착수 명령을 주시면 브리핑을 진행합니다.
```
